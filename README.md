# 申论进阶 · Shenlun Studio

可部署在 Mac mini Docker Desktop 上的个人申论训练应用。试卷、原答案与批改历史保存在本机；仅主动调用模型时，将相关材料发送给你选择的 API。界面无需访问外部 CDN。

## 不使用 git clone 的安装方式（推荐）

在 Mac mini 安装并启动 Docker Desktop 后，终端运行：

```bash
curl -fsSL https://raw.githubusercontent.com/krbedison-cloud/writing/main/install.sh | bash
```

安装器优先拉取 `ghcr.io/krbedison-cloud/writing:v0.1.33` 多架构镜像，Docker 自动选择 M 系列的 ARM64 或 Intel 的 AMD64。若 GHCR 尚未开放匿名拉取，会从公开的 GitHub Release 下载对应架构的预构建镜像并执行 `docker load`；发行文件仍在生成时才下载同版本源码归档并在本机 `docker build`。整个过程不需要 Git、Python 或 Node。

配置保存在 `~/shenlun-studio/.env`，程序只监听本机 `18086` 端口；数据使用 Docker 数据卷 `shenlun-studio-data`。安装脚本会输出实际访问地址和停止命令。重复运行安装命令不会覆盖已有 `.env`；如版本配置文件已有人工修改，会停止而不是覆盖。发布的新版本可以通过再次执行安装命令更新，既有数据保留。

不希望通过管道执行脚本时，可先下载并查看再执行：

```bash
curl -fL https://raw.githubusercontent.com/krbedison-cloud/writing/main/install.sh -o install-shenlun.sh
bash install-shenlun.sh
```

已有安装或需要指定端口时，执行下面命令，仅更新端口并保留其他配置、密钥和数据：

```bash
curl -fsSL https://raw.githubusercontent.com/krbedison-cloud/writing/main/install.sh | SHENLUN_PORT=18086 bash
```

也可把 `18086` 换为其他 1–65535 的空闲端口。未指定 `SHENLUN_PORT` 时，已有 `.env` 的端口保持原值；全新安装默认使用 `18086`。

使用自定义安装目录：

```bash
curl -fL https://raw.githubusercontent.com/krbedison-cloud/writing/main/install.sh -o install-shenlun.sh
SHENLUN_DIR="$HOME/Applications/shenlun-studio" bash install-shenlun.sh
```

公开镜像可直接拉取：

```bash
docker pull ghcr.io/krbedison-cloud/writing:v0.1.33
```

GitHub Actions 在推送 main 时运行测试，根据 `VERSION` 构建两种架构镜像并创建对应标签的 Release。发布新版本时同步更新 VERSION、安装脚本默认版本与部署配置。GHCR 首次创建的包可能是私有的；仓库拥有者可到 GitHub 的 Packages → writing → Package settings 将包设为 Public，之后无需登录即可拉取。即使没有更改包的可见性，上面的安装器仍能使用公开 Release 中的预构建 Docker 镜像完成安装，不必登录 GHCR。

## 局域网内访问

在运行 Docker Desktop 的 Mac mini 上执行：

```bash
curl -fsSL https://raw.githubusercontent.com/krbedison-cloud/writing/v0.1.33/install.sh | SHENLUN_LAN=1 SHENLUN_PORT=18086 bash
```

安装器会保留已有数据和其他配置，持久设置 `APP_BIND=0.0.0.0`、`ALLOW_LAN=1` 以及指定端口。Docker 会在 Mac 所有 IPv4 接口监听 `18086`，应用允许以私有局域网 IP 访问；原来的主机白名单和同源写入检查仍有效。IP 变化后通常不需要重新配置白名单。

完成后安装器会列出实际的局域网地址，例如 `http://192.168.1.20:18086`。同一局域网的其他电脑使用此地址；Mac mini 自己也能继续使用 `http://localhost:18086`。例子中的 IP 需要换成你自己的 Mac 地址。若没有自动显示，可在 Mac 系统设置 → 网络 → 当前连接 → 详细信息中查看 IP，或执行 `ipconfig getifaddr en0`。

Mac 防火墙如提示 Docker 接收入站连接，选择允许。设备需要网络互通；访客 Wi-Fi、路由器的 AP 隔离或 VLAN 隔离可能阻止设备互访。若希望地址长期固定，可在路由器为 Mac 配置 DHCP 地址保留。

所有访问者共用同一份题库、模型配置和练习历史，未实现独立用户账号。已有 `APP_PASSWORD` 原样保留，设置过密码时仍使用 `admin` 和原密码；可在 `~/shenlun-studio/.env` 设置或修改它，再运行安装器使其生效。局域网模式自动接受 RFC1918 IPv4、IPv4 链路本地和私有 IPv6 字面地址；使用自定义域名或其他 IP 时，另加到 `.env` 的 `ALLOWED_HOSTS` 中。

恢复仅本机访问：

```bash
curl -fsSL https://raw.githubusercontent.com/krbedison-cloud/writing/v0.1.33/install.sh | SHENLUN_LAN=0 bash
```

未指定 `SHENLUN_LAN` 时，保留现有的访问模式。

## 在 Mac mini 上启动

安装并启动 [Docker Desktop for Mac](https://www.docker.com/products/docker-desktop/)，将本仓库放到 Mac，终端进入仓库目录：

```bash
cp .env.example .env
docker compose up -d --build
```

在 Mac 浏览器打开 `http://localhost:18086`。默认仅监听本机，Apple Silicon（M 系列，arm64）和 Intel（amd64）使用同一份配置，无需指定 `platform`。应用本身建议至少分配 2 GB 内存；本地运行大模型需要另计内存。

```bash
docker compose ps
docker compose logs --tail=80
docker compose down                  # 停止，保留数据
```

首次构建需要下载 Python 依赖和中文 OCR。若端口占用，在 `.env` 修改 `APP_PORT` 后重新启动。更新代码后再次运行 `docker compose up -d --build`。不需要 Node、数据库服务或 GPU。

## 使用流程

1. **模型设置**：添加任意数量接口，每个配置对应一个具体模型。输入名称、协议、API 根地址、模型 ID、密钥并测试连接。相同服务商的不同模型可以分别添加。
2. **真题练习 → 导入 PDF**：提取文字；扫描页使用内置 Tesseract 中文 OCR。规则自动识别年份、省份、卷别与题目，并按题干引用关联各题材料。也可选择模型进行 AI 识别；这会将完整试卷文本发送给该模型。
3. **校对试卷**：核对原题、给定材料、来源、字数和训练档。可调整题型、增减题目。勾选确认后开始作答。自动识别结果始终需要确认，不会把不确定的题目当作正确答案。
4. **作答**：浏览材料，输入答案；当前浏览器自动保留草稿。勾选多位批改模型（单次最多 12 位），选择一位主模型，提交后原答案立即存档。
5. **批改报告**：各模型独立打分，提供六维评价、具体扣分证据、改进建议与自己的参考范文；主模型基于这些结果和你的原答案进行汇总。程序计算有效模型的算术均分和最高最低分差。
6. **练习历史**：回看每次原答案、当时题干与材料快照、模型身份、评价与范文。修改试卷或模型名称不会改写既有结果。支持导出全部试卷和历史 JSON（不含 API Key）。
7. **能力与竞争力**：每次有效批改后，主模型自动分析全部历史摘要，更新长期诊断；数值统计即时更新。也可手动更新文字诊断。

### 长文阅读与作答布局

材料、题干、答案和批改长文默认采用 20px 正文、两倍行距；按钮和辅助说明同步放大并加强文字对比。右上角“阅读设置”支持：

- 18 / 20 / 22 / 24px 正文字号，1.8 / 2 / 2.2 倍行距；
- 系统黑体或宋体，以及暖纸、浅白和夜读背景；
- 电脑左右对照、手机自动上下的布局，或手动选择更宽的上下阅读布局。

作答页的“专注作答”可收起侧栏、扩大阅读和书写区域，顶部按钮或 Esc 退出。每个阅读区只保留一层滚动；批改模型设置默认折叠，标题显示已选教练数，展开即可调整。

PDF 内文的硬换行仅在显示时整理为段落；原始材料、题干、存档和 API 输入保持原样。设置保存在当前浏览器中；调整设置不会重新载入作答页或清空草稿，不同电脑可分别选择自己的字号与背景。

### 按本题审题批改与实时结果

20 / 30 / 50 分只是训练满分，不决定具体文体。每位教练先解析本题题干的任务、作答对象、文体、内容、格式和字数，再从本题所选材料提炼要点，对照原答案给出扣分证据。概括、分析、短评、提纲、文章等依各自题干评价，不对所有题强加标题、称呼或落款。模型返回的审题分析会显示在详细批改中；汇总模型同样需核验审题与材料依据，指出错误文体要求。该流程不增加一次专门审题的 API 调用。

批改尚未完成时已返回的教练结果可阅读。后台只更新变化的状态、评分、汇总或结果区域，保留当前教练、范文版本与已展开的题干快照；新教练到达不会重建当前范文纸面。范文原文与25格纸面默认直接并排展示，窄屏上下排列，不再折叠。

更新不会重算旧分数或自动付费重批。旧版批改记录保留原答案、分数及范文，并提示可回原题用原答案重新提交；重试失败项仍只重试失败教练，已成功的旧结果不会被悄悄改写。新批改记录保存提示策略版本，便于区分旧版评价。

模型输出兼容：数字字符串（如“16分”）、包含明确score字段的维度对象、维度记录列表，以及以整段文字返回的建议列表会无损转为程序需要的结构。缺失/不完整的可选审题分析不会作废有效评分，报告会提示其缺失。总分和六维分仍需合法且在范围内，缺失核心评分证据或高分答案仍会失败；不会补造评分、自动缩放或截断越界分数。结构错误会显示具体字段及原因，不展示模型原始返回或密钥；可用该教练的“单独重试”重新请求。

批改进度：教练卡片分别显示排队等待接口、批改请求中、评分校验、范文校正、完成或失败，并显示阶段等待时间、总用时与模型响应耗时。排队等待不计入模型请求超时；排队状态来自全局4请求并发限制。token用量仅展示接口实际返回的数字，不模拟模型内部思考进度或完成百分比。

速度优化：评分与初版范文通过校验后立即存档展示，不再等待自动范文校正；主模型汇总与范文校正可以并行，汇总完成后先展示，校正仍在进行时保留后台状态。只压缩重复的审题/评语，不省略本题材料或范文最低字数要求。提高token上限本身不等于加快模型生成速度，实际耗时取决于服务商及所选模型。原答案、成功评分与范文版本仍保留，截断不会按零分计入均分。

### 材料高亮、25格稿纸与范文校验

**材料高亮**：在作答页选中一段材料，悬浮工具中点“高亮”。默认亮黄色，可先用颜色控件选其他颜色；重新框选已有高亮时，主操作变为“取消高亮”，不会重复添加。选区跨越多处标注时会取消这些标注；点击一处高亮还可更新颜色或取消。标注按题保存在服务器 SQLite 中，刷新、容器升级或换一台局域网电脑后仍能读取。文字位置采用材料指纹和 Unicode 字符锚点；材料实质变更后，旧标注保留归档而不错误套用到新文字。高亮不会被额外发送给模型。

**25格答题纸**：每行固定25格，默认行数为题目字数上限除以25后向上取整。300字12行、350字14行、500字20行、600字24行、1200字48行。在“校对试卷”中可为每题设置实际纸面行数，0表示自动。这个表是本软件的默认训练纸面规则；实际答题卡行数应以原卷为准。

原文作为一个连续答案保存，支持中文输入法、粘贴、删除、撤销与选择；可随时切换“原文编辑”，统计规则不变。工具栏提供空两格、顶格、标题居中、落款右对齐；标题先输入再点居中。Enter换段默认空两格，可关闭；Tab插入两格，Shift+Tab或Esc可离开稿纸输入。

原文编辑中输入超量内容后切回格子纸，超出部分仍完整保留并标红；支持跨行、跨栏拖选及 Shift+点击扩选，拖到行尾外或格间留白也不会漏掉尾部内容。出现纸面超限时，工具栏显示“选中超出部分”：点击后可见蓝色选区（暖纸和夜读模式均支持），再按 Backspace 可一次删除，支持撤销。选区按实际占格确定，包含超出的换行、空行和缩进，不会把正常容量内的答案一起删掉，也不会自动截断答案。

电脑默认左右对照，材料区独立滚动，完整答题纸根据窗口宽高自适应铺开，没有纸面内部的横向或纵向滚动条。方格保持正方形，采用作文纸的朱红格线、行间留白和双线边框；长作文自动分栏，按行号从上往下、从左到右连续书写，每行始终25格，分栏不增加答题格数。格内字号以阅读设置为上限，随可用空间调整；材料仍使用所选正文字号。较窄的电脑窗口会自动收起左侧导航，鼠标移至左边“导航”标签展开、移出收起，也可用键盘或点击标签操作。手机或手动选择“上下阅读”时，两区上下排列，纸面同样完整铺开。

新练习采用中文稿纸规则：汉字通常一格；连续半角英数每两字符一格（`1.` 合一格、`2026` 两格），短数字串/英文词尽量整体换行。行末点号及后引号/右括号逻辑上归入末字格，汉字保持与其他格相同的正常字号，标点独立悬挂于右侧预留留白，不缩小汉字或整组文字；前引号/左括号不孤立行末；`——`、`……` 各占两格且不拆行。显式换行仍按原文保留，段首缩进和落款用实际空格表示。字数按非空白字符逐个统计，合格不会让字数计数减少；同时显示实际占格及格式空耗。已有带旧版纸面快照的历史记录沿用旧规则，避免重写当时校验。

规则依据和具体训练约定见 [中文稿纸排版说明](docs/chinese-manuscript.md)。这不是所有省份统一的官方答题卡规则；实际答题卡及考场要求优先。

**范文双重校验**：独立批改模型必须按题干字数、文体及纸面规则生成纯文本范文，并返回自身的字数、占用行数和格式自检。程序再独立计算字数与纸面占用，模型自报数字不同会明确标注；同时校验“不足300字”为最多299字。标题居中和落款对齐须用实际全角空格表示，不能把格式空耗忽略。

若程序发现新范文不合规，会向同一模型最多追加一次只修订范文的请求；仍不合规就显示具体原因，不把它标成合格。旧报告打开时只做本地规则计算，不自动付费改写。

范文下的“字数少了”“字数多了”按钮会单独要求原模型补充或压缩，并再次校验纸面；不会重新批改、重算分数或改变原答案。每次请求以及可能追加的1次修订按实际API用量计费。范文版本列表保留原始答案和历次重写结果，可查看每版25格纸面预览。多台设备对同份作答发起范文重写时会串行保护，避免结果互相覆盖。

### 每题单独使用材料

上传后按“材料1 / 资料一”等标题拆分段落，并读取每道题的引用范围，支持“资料3”“资料8、9”“材料一至三”等常见写法。使用提供的 2026 浙江 A 卷实测：

| 题目 | 使用的材料 | 材料长度（字符） |
|---|---|---:|
| 第一题短简报 | 仅资料 3 | 1129，较整卷 8159 减少约 86% |
| 第二题短评 | 仅资料 8、9 | 2410，减少约 70% |
| 第三题大作文 | 按题干要求使用全部材料 | 8159 |

答题页仅加载并展示当前题的材料与题干；每位模型的批改输入仅包含本题材料、题干、原答案和评分规则，不再发送其他题目或无关资料。主模型汇总复用相同材料，并接收各模型的评价；参考范文完整存档和展示，但不重复塞入汇总请求。上表比较的是材料字符长度，不是实际 token 或费用统计。

在“校对试卷”中，每题可选择自动匹配、手动勾选资料编号、全部材料，或人工粘贴本题材料。引用缺失、段落标题重复或无法可靠拆分时，页面会提示核对并保留全文，避免悄悄漏掉依据；可手工修正后再提交。

升级后，旧试卷自动补上材料关联，不需要重新上传；已存档的答案、题干与材料快照不被改写。之后修改材料选择只影响新作答，每次提交都会保存当时实际使用的材料。

### 训练档与预估方式

按用户确认的训练结构归类，保留原题文体要求：

| 训练档 | 满分 | 示例 |
|---|---:|---|
| 概括 / 短简报 | 20 | 短概括、350 字简报 |
| 应用文 / 短评 | 30 | 公文、500–600 字短评 |
| 大作文 | 50 | 1000–1200 字议论性文章 |

已用提供的《2026年浙江省公考〈申论〉题（A卷）》验证：17 页可直接提取文字；第一题短简报 350 字、第二题短评 600 字、第三题大作文 1000–1200 字分别归入 20 / 30 / 50 分档。原题即使分数不同，也按训练档评分。

- 六维：审题立意、要点提炼、材料运用、结构逻辑、语言表达、文体规范。先对每次作答的有效模型维度分求平均，再对全部有效作答等权平均，每维满分 100。
- 浙江三题预估：在“能力与竞争力”选择预测模型，点击“更新预测分”，由模型根据历次评分、六维能力变化和诊断摘要预测三类题型表现，再合计为100分。练习均分仅作参考，不直接作为预测分；缺少题型证据时不硬估总分。页面刷新、新增批改和后台任务都不会自动调用预测API，已有结果保留至下次手动更新。
- 失败模型不计零分；只要存在有效批改，该作答即可参与统计，即使主模型汇总失败。报告标明成功数量、缺失结果和模型分差。
- XP 每份成功批改的新答案 +25；同题同答案不重复奖励。每 100 XP 升一级。等级代表坚持，分数代表本次表现，均不代表真实竞争排名。
- 这是一套训练估计，不是经过真实考场样本校准的预测模型。题目难度、反复作答和模型偏差会影响结果；建议固定模型组观察趋势。没有真实考生样本时，不生成百分位、排名或上岸概率。

## 接口配置

| 协议 | API 根地址示例 | 说明 |
|---|---|---|
| OpenAI 兼容 | `https://api.openai.com/v1` | 追加 `/chat/completions` |
| OpenAI 兼容 | `https://api.deepseek.com/v1` | 其他兼容平台按其文档填写 |
| Anthropic | `https://api.anthropic.com/v1` | 追加 `/messages` |
| Gemini | `https://generativelanguage.googleapis.com/v1beta` | 追加 `/models/{模型ID}:generateContent` |
| OpenAI 兼容 / Ollama | `http://host.docker.internal:11434/v1` | Mac 宿主机的本地模型；密钥可留空 |

模型 ID 请向服务商确认，不能填产品显示名称。选择能输出 JSON、上下文足够容纳整份试卷的文本模型。新接口默认输出上限32768 tokens，可设置1000–131072，须在服务商实际支持范围内；已有接口的自定义值保留。推理模型的思考token也可能消耗输出预算。截断报错会显示本次上限及接口提供的用量，失败教练卡片可点击“提高至…并重试”，只提高这家模型配置并重试该教练；也可在模型设置手动调整。程序对返回结构、六维范围、题目满分与输出截断进行校验。部分 OpenAI 兼容服务不支持 `max_completion_tokens` 时，自动改用其支持的 `max_tokens` 重试。

每份答案通常调用“所选模型数 + 主模型汇总 + 主模型画像”次；范文不合规时每个模型至多追加1次修订；可选的 AI 试卷识别另外调用。画像的输入包含全部有效历史的压缩证据；记录很多时采用分块汇总。服务商按实际 token 计费，应用不包含 API 额度。每个模型的单次请求等待上限默认600秒，可在“模型设置 → 编辑 → 等待时限（秒）”设置60–1800秒；旧配置自动采用600秒，无需重填密钥。等待上限覆盖整次调用，OpenAI兼容参数重发也共用该时限。全局最多4个并发API请求。批改与画像是后台任务，关闭浏览器不影响执行。

某个模型失败后，可点击该教练卡片上的**单独重试**，只重跑这一家的独立批改，其他成功结果与失败记录保留；**重试失败项**仍支持一起重试全部失败教练。同一作答仍在批改或生成范文时，重试按钮暂时禁用，完成后再试，避免任务互相覆盖。重试完成会重新计算成功均分，并更新汇总诊断与画像，后两项按实际调用计费。全部教练成功但汇总失败时，**重试汇总**只重新汇总，不重复独立批改。服务重启会把正在执行的任务标记为中断，保留作答与已完成结果，允许手动重试。重试时接口协议、地址和模型 ID 必须与提交快照一致；避免把新模型混进旧评分。密钥和等待时限可以更新；调高慢模型的等待时限后，可直接重试该教练。

## 保存、备份与访问控制

数据保存在 Compose 命名卷 `shenlun-data`，容器路径 `/data`，包括：

- `writing.db`：SQLite 试卷、答案、模型配置、批改结果、范文版本、材料高亮、任务与画像；
- `master.key`：加密 API Key 的本地密钥，首次启动生成；
- `uploads/`：原始 PDF。

重建容器和 `docker compose down` 保留数据。**不要运行 `docker compose down -v`**，该命令会删除数据卷。应定期备份整个目录，数据库和 `master.key` 需成对保存。不要把数据卷、备份、`.env` 或真实密钥提交到 Git。密钥加密属于本地应用保护，不能抵御已能读取整个数据卷的人。

在仓库目录备份（先停止服务保证 SQLite 文件一致，避免遗漏 WAL）：

```bash
mkdir -p backups
docker compose stop
docker compose cp shenlun:/data "./backups/data-$(date +%Y%m%d-%H%M%S)"
docker compose start
```

完整恢复时，先停止服务，将备份内容放回 `/data` 并确保属主为容器用户 UID/GID `10001` 后再启动。应用内 JSON 导出适合阅读与归档，不包含密钥和原 PDF，**不是完整恢复包**。

`.env` 可设置 `APP_PASSWORD`，浏览器会要求用户名 `admin` 和此密码。默认仅本机访问；局域网共享使用上面的 `SHENLUN_LAN=1` 安装命令，可按需设置访问密码。通过带 HTTPS 的反向代理访问时，需要配置正确的 Host 和转发协议。当前定位是单人私有应用，未实现多人账号与权限隔离。

## 实现与边界

FastAPI + SQLite + 原生 JavaScript/CSS；PyMuPDF 提取，Tesseract 中文 OCR；无外部前端依赖。题目归类提供规则默认值、可选 AI 辅助与人工校对。PDF 中的文字作为待分析数据，模型提示中明确禁止将其当作系统指令。

单文件最大 25 MB / 80 页，提取文字最大 16 万字符；单次模型上下文保护上限 16 万字符（仍需模型本身支持相应上下文）。复杂排版、手写、模糊扫描件可能识别不准，请校对或先 OCR；应用接收键入/粘贴的答案，目前不做手写答案识别。范文为各模型生成的参考文本，未接入官方评分库。

上传后如识别到多段编号材料、但题干未明确材料范围（含大作文），会自动打开校对窗口，请逐题选择“材料几到几”、勾选不连续材料，或明确选择“全部材料”。未确认范围前不能提交批改；历史作答快照保留。AI 重新识别在题干未改变时保留人工材料选择。

API 辅助识别兼容数字年份、中文训练题型、空值字数、文字段落数组及常见 JSON 外层包装；题干、题号等核心内容仍须有效。格式不符时最多自动重新提取一次，失败会提示具体字段并保留原试卷，不自动重试超时和接口错误。

汇总诊断兼容最多64条有效建议，提示词优先要求不超过5条，避免原先超过8条即失败。AI 长期观察仅展示简短趋势、2条优势、2条短板和3条训练重点；历史证据逐次保留日期、分数、六维指标及去重后的短要点，减少输入长度，较大历史仍分组汇总。旧版画像需要点击“重新生成要点”按新版要求重写。

长期观察现按完整中文短句生成：一句当前结论，最多2条优势、2条短板、3条训练动作。程序不再按字符截断显示；模型复述统计、夹带内部编号、输出省略号或长段落时，最多自动重写一次（仅发送草稿），仍不合格则保留已有观察。历史输入不再包含作答内部ID。旧版长报告在页面提示重新生成，不冒充新版要点。

短评（含简评、时评、简短评论）按题干的写作任务识别，高分范文正文采用总分总五段：开头＋三个分论段＋结尾，各分论段先写总结性前置句。案例须根据本题材料适度抽象为“主体—行动—意义或效果”，保留关键做法与真实因果，不照搬具体数量、金额、比例等数据，不空泛或虚构。首次范文、自动修订和所有单独重写共用该要求；程序检查正文段数及明显数量表达，不符时最多自动修订一次，仍不符则保留结果并展示提醒。段首观点与案例是否恰当仍需结合模型自检及原材料核对。此训练偏好仅用于范文，不作为用户原答案的额外扣分条款。旧练习可点击“重新生成范文”应用当前规则，原答、分数和旧范文版本保留。

练习页自动开启秒表，本题累计用时保存在当前浏览器，刷新或再次进入同题可继续；“重新计时”仅清零秒表。默认5分钟没有操作后显示暂停作答界面并停止计时，可选择3/5/10/15分钟；鼠标移动、键盘输入、滚动材料和触屏操作均可立即恢复。切换后台或离开练习页时暂停，离开和暂停期间不累计用时。自动暂停只由用户活动判断，后台批改状态或页面轮询不会延长作答时间。

接口额度不足或失效时，可在失败教练卡片点击“更换接口重试”，选择其他已配置接口单独补批；旧接口配置已经删除也支持替换。直接编辑失败接口的地址、协议或模型后，点击“单独重试”会按当前配置执行。成功的教练评分、参考范文和原答案保留，结果按实际模型标注；旧失败记录和接口更换记录保存在本次作答详情和导出中，不包含密钥。同一接口不能同时占用两位教练的评分位置。

若被更换的失败接口同时承担汇总，新接口会一并负责汇总；汇总失败也可以单独点“更换汇总接口”，只更新汇总而不再次请求各教练评分。补批后重新计算均分并生成汇总。执行中的任务仍需等待结束，避免并发覆盖结果。

大作文评分使用自定义50分校准：30分一般，33分二类文起点（论点准确、框架合理、论述自洽无明显瑕疵），35分二类中上，36–38分要求论点递进、论证严密深刻、表达简明规范且文笔较好；38分以上极罕见，须提供突出表现的原答证据。分档是模型判断锚点，程序不保底、不压分、不把38当硬上限；四个分论段不构成扣分理由。新评分带有校准标记，旧成功评分保留。

大作文范文默认总分总、三个分论段，必要时可四个；每段先写总结性观点句，重说理论证与评论，典型案例只从本题材料择取，概括主体、行动与作用，不列具体数据、不堆砌或过度泛化。首次生成、自动修订和单独重写共用紧凑规则。范文另行严格校验1001–1200字与25×48格，标题、缩进、换行空耗都计入1200格；可在字数范围内仍因纸面超限而提示修订。原答案按原题纸面要求评价，原有题干和历史纸面快照不改写。建议范文约1050–1120字以留出格式空间。

评分校准仅在需要评分/汇总时发送，重写范文不发送整套评分规则；公共提示已压缩，材料每次仅发送本题一份，范文格纸规则与题目相同时不重复传输长规则文本，自动修订仍限一次。

智谱官方地址 `https://open.bigmodel.cn/api/paas/v4` 的 OpenAI 兼容请求直接使用 `max_tokens`。其他 OpenAI 兼容服务继续优先使用 `max_completion_tokens`，仅在明确报告不支持参数时回退一次，共享原来的超时预算；不自动缩小用户设置的输出上限。400等错误按已识别的参数、额度、权限、上下文等原因给出提示，可显示白名单错误码与本次输出参数，不保存或展示响应原文、密钥或作答反射。GLM-5.3 官方文档列出最大输出128K，并默认启用思考，不能仅凭配置131072认定本次错误就是超限。参考：https://docs.bigmodel.cn/cn/guide/models/text/glm-5.3 。

大作文取材优先级更新：先保证论点准确与层次递进，再尽量利用题内材料；无法支撑论点的材料可以舍弃，不追求全覆盖。仅当材料确实缺乏可用典型案例（如材料过短）且题干允许时，可少量补充知名、代表性、事实可靠的事例，构思说明必须标明材料外补例与必要性；不编造细节或数据。短评仍只用题内案例，其余评分、结构与字数/格纸限制保留。

高分范文现在同一次请求返回独立的构思说明（论点框架、递进串联、逐份材料用法与舍弃原因），通常200–400字，小题更短。说明显示在范文之后，不计入字数或格纸，随对应范文版本和模型存档，主模型汇总不再重复接收这部分文字。旧范文或缺说明的版本可点“生成构思说明”单独补充，不重批或改文。说明是面向读者的结构讲解，不是模型内部思考日志。

性能优化：短评提示做了语义压缩；模型保留必要构思与论证，只返回最终自检结果，程序仍精确核验纸面并保留一次自动修订；请求JSON移除结构空白，稳定的任务规则在前、题干材料次之、用户原答在末尾，以利支持自动前缀缓存的服务商复用，实际缓存是否命中以接口usage为准。新增输入、缓存、输出及思考token计数。新增说明本身会增加必要的输出，因此不承诺每次总token或耗时都降低。

智谱官方GLM-5.3默认思考强度为max，可能是思考耗时较长的来源之一。“模型设置”可选择服务商默认、low、high、max；旧配置默认不变，不自动降低推理强度。只有该官方模型发送reasoning_effort字段，其他接口不发送。low更快但可能减少推理深度，可按需求选择high或max。输出上限和超时设置不变。参考：https://docs.bigmodel.cn/cn/guide/models/text/glm-5.3 。

接口编辑界面只在协议为 OpenAI 兼容、地址为智谱官方且模型为 GLM-5.3 时显示思考强度。DS、Kimi、第三方代理及其他模型不再显示智谱选项，也不发送该参数；修改协议、地址或模型后即时更新显示。


应用文30分评分校准：继续以本题材料与任务踩点给分，同义或有效抽象概括同等给分，同一缺陷不重复扣分。短评以17–19分（框架结构基本正确但语言欠准确简练、存在漏点）、20–22分（论点总结正确、能概括案例、评论基本准确）、23–25分（开头、段首观点、案例运用、评论与结尾均更出色）为质量参照；25分以上仅用于有充分原答证据的特别优秀答案。其他应用文按相同质量层次类推，以各自任务、对象、信息与格式判断，不强加短评的对仗、案例或升华。

分档为自定训练标准，不设17分保底或25分封顶，不统一打折，也不先定档倒推扣分。每位教练和主模型汇总都收到同一校准，程序仍保留各模型实际合法分数并计算算术均分。标准每次只作为一个独立字段发送，不增加API调用。新批改标记为`practical-v1`；旧记录和重试中已经成功的评分保留，旧标准记录会提示，新版范文重写不会改分。


范文独立构思：首次批改仍用同一次请求，提示模型先依据本题题干、材料及范文规则生成高分答案和构思说明，再给用户原答评分。原答仅用于评分、证据和改进建议，不作为范文的底稿、提纲、事实来源或要点边界；不能继承原答的错误、遗漏，也不为追求不同故意避开材料中的正确要点。仅靠同一请求中的提示不能完全隔离模型已读到的原答，因此没有把这种方式描述为严格的数据隔离。

“重新生成范文”请求只携带本题题干材料和范文规则，不发送用户原答、旧范文、旧范文检查或其目标字数，从题目重新构思。“字数少了/多了”和自动校正只携带模型旧范文，明确标为`previous_reference`，依原题和纸面限制调整；评分与原答案保留。专门的短评/大作文结构、前置句、案例概括、材料取舍、既有大作文补例例外、字数/占格和构思说明要求均保留。

提示优化以职责分明、移除重复格式说明及不必要旧范文输入为主，保持模型思考强度、输出上限、完整材料和功能不变。请求按“任务规则→题干材料→其余规则→用户原答”组织，便于支持前缀缓存的接口复用；实际缓存、token与耗时以服务商返回为准。首次批改没有新增调用；重新生成省去一整篇旧范文输入，不承诺模型质量或耗时的固定提升幅度。


大作文同卷取材偏好：根据本套试卷前面非大作文小题已确认的材料范围，将本题可用材料分为优先与辅助两组，不要求先练过小题。范文优先用未涉及材料构思论点、递进框架和主要案例；仅当它们不足以完整准确支撑框架与论证时，才适量补用前题材料，并在构思说明中解释必要性。题干明确必用材料优先，不为避重牺牲论点质量，也不以材料外案例绕过可用的本题材料。此偏好只用于范文，原答按原评分标准评价。

优先级由程序本地计算，仅额外传递简短编号，不发送其他小题的题干、答案或重复材料，不新增API调用。人工选范围优先；人工粘贴材料须能与原编号材料完整对应，否则提示范围不可靠并正常取材，不猜测禁用。所有本题允许材料仍完整传给模型；若前题已涉及全部材料，也按本题需要正常使用。

新作答保存提交时的优先级快照，后续编辑源试卷不改旧作答；各范文版本保留自己的优先级并在界面展示。旧作答没有该快照时，仅在源试卷的大作文题干与完整材料仍匹配的情况下，按当前校对范围为新范文计算，并明确标注；不匹配时正常取材，不回写旧快照、范文或评分。
